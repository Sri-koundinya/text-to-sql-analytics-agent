# Text-to-SQL Analytics Agent

Ask a business question in plain English and get back the SQL that answers it, the result table, and a one-line explanation. The query runs against a PostgreSQL retail database.

The project is set up the way a customer deployment would be. The LLM's SQL is treated as untrusted input, and it passes through five independent safety layers before it touches data. The database ships with realistic, deterministic seed data so that accuracy can be measured and reproduced.

## Architecture

```
Streamlit chat UI  ──HTTP──▶  FastAPI backend  ──▶  OpenAI Responses API (SQL generation + repair)
   (frontend/)                 (backend/)       ──▶  sql_guard (sqlglot) ──▶ PostgreSQL 16 as analytics_reader
```

1. The backend reads the live schema. It only sees the tables `analytics_reader` is allowed to read.
2. The model returns `{"sql", "explanation"}` as JSON.
3. The SQL is validated and wrapped. If it is rejected or fails at runtime, the error goes back to the model for a repair attempt (up to `MAX_SQL_RETRIES`).
4. The query runs in a read-only transaction. The rows, the SQL and the number of attempts are returned.

## SQL safety layers

| # | Layer | Where |
|---|-------|-------|
| 1 | sqlglot parse: exactly one `SELECT`/CTE/set operation; no comments, DDL/DML keywords, `SELECT INTO`, row locks or dangerous functions (`pg_sleep`, `dblink_*`, `lo_*`) | [backend/app/sql_guard.py](backend/app/sql_guard.py) |
| 2 | Table allow-list taken from the schema the reader role can see (CTE names allowed) | [backend/app/sql_guard.py](backend/app/sql_guard.py) |
| 3 | The query is wrapped in an outer `LIMIT`, so the model cannot remove the row cap | [backend/app/sql_guard.py](backend/app/sql_guard.py) |
| 4 | `SET TRANSACTION READ ONLY` plus `SET LOCAL statement_timeout` on every query | [backend/app/database.py](backend/app/database.py) |
| 5 | The app connects as `analytics_reader`, which only has `SELECT` on the four tables, never as the admin user | [db/init.sql](db/init.sql) |

Layers 1–3 are covered by [backend/tests/test_sql_guard.py](backend/tests/test_sql_guard.py). The API also rate-limits requests per client IP and hides raw errors unless `DEBUG=true`.

## Quickstart

Requirements: Docker Desktop and an OpenAI API key.

```bash
cp .env.example .env
```

Edit `.env` and set `POSTGRES_PASSWORD` and `OPENAI_API_KEY`. Then:

```bash
docker compose up --build
```

- Chat UI: http://localhost:8501
- API docs: http://localhost:8000/docs
- Health check: http://localhost:8000/health

All ports bind to `127.0.0.1` only. The schema and seed run once, on first start. To rebuild the database from scratch:

```bash
docker compose down -v && docker compose up --build
```

### Running the backend tests

```bash
cd backend && pip install -r requirements-dev.txt && pytest
```

### Running without Docker

Load `db/init.sql`, then `db/seed_large.sql`, into a Postgres database named `retail_analytics`. Then run the backend from `backend/`:

```bash
export DATABASE_URL=postgresql+psycopg://analytics_reader:analytics_reader@localhost:5432/retail_analytics
uvicorn app.main:app --reload
```

Start the frontend with `API_BASE_URL=http://localhost:8000 streamlit run frontend/app.py`.

## Dataset

A fictional Indian omnichannel retailer, 2023–2025. It is generated by [db/seed_large.sql](db/seed_large.sql) using `setseed`, with explicit row ordering and parallel query disabled. The same script produces byte-identical tables on every run.

| Table | Rows | Notes |
|-------|------|-------|
| `customers` | 2,000 | 14 cities, weighted toward large metros; signups 2023-01 to 2025-06 |
| `products` | 48 | 8 categories (Electronics, Home, Sports, Apparel, Toys, Beauty, Books, Grocery) |
| `orders` | 24,822 | 86% completed, 9% cancelled, 5% refunded; volume grows over time, with a Q4 festive bump; no order predates its customer's signup |
| `order_items` | 40,745 | 1–4 lines per order; popularity skew; about 12% of lines carry a 10% discount |

Reference fingerprint, for checking that a load matches. Compute it with `md5(string_agg(row::text, '|' ORDER BY row::text))` per table (verified on PostgreSQL 17):

| Table | md5 |
|-------|-----|
| customers | `d293b0811611025f38b7a7a344ec1cc6` |
| products | `77bfacd20c598055af4eb966b1693f98` |
| orders | `1cbd78c5a04906f2f6c3d06bfe498187` |
| order_items | `e5796ff4aca8d462dd46313a1f03450a` |

Completed-order revenue is about ₹0.38M in 2023, ₹1.08M in 2024 and ₹1.25M in 2025. Electronics is the largest category.

## Configuration

All configuration goes through environment variables. See [.env.example](.env.example) and [backend/app/config.py](backend/app/config.py). Secrets live only in `.env`, which is git-ignored. For a managed database, create the reader role with [db/production_reader_role.sql](db/production_reader_role.sql) and pass the password at run time.
